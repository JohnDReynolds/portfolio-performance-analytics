# Performance Comparison Checkpoint Notes

These are historical checkpoint notes from earlier implementation sessions.
They are useful for continuity, but they are not the active roadmap. Current
future work belongs in
[`performance_comparison_roadmap.md`](performance_comparison_roadmap.md).

## Historical Checkpoint State

At this checkpoint, the performance comparison XLSX work was workbook-first. For bundles
generated with `--include-workbook`, reviewers should start with
`report.xlsx`; `report.html` is a browser-friendly view of the same review
model, and CSV files are audit/export artifacts.

The workbook sheets at this checkpoint were:

- `Performance Differences` sheet: portfolio-period return differences, explained
  difference, unexplained difference, status, and comments.
- `Performance Differences` sheet: security-period return differences, including
  explicit no-security-difference rows for changed portfolio periods.
- `Performance Difference Causes` sheet: input rows that may explain portfolio
  differences, with `Performance Difference Explained` when ppar has a
  defensible calculation.
- `Raw Audit Trail` sheet: full finding-level detail.

Workbook numeric cells were real Excel numbers where possible.

## Key Decisions

- Treat `report.xlsx` as the primary reviewer artifact.
- Keep `report.html`, CSV files, and `manifest.json` for browser, audit, export,
  and validation uses.
- Keep `openpyxl` as a regular runtime dependency because XLSX is the primary
  reviewer surface.
- Keep lower-level bundle workbook generation opt-in with `--include-workbook`
  for custom bundle commands.
- Keep the workbook action-oriented: "This is the performance difference, and
  this is what explains it."
- Keep deep diagnostic fields such as `Code` and `Review Rank` in
  the `Raw Audit Trail` sheet, not in the main action sheets.
- Use the same left-side sort fields for the `Performance Difference Causes` sheet,
  and `Raw Audit Trail` sheet: `Portfolio`, `From Date`,
  `Thru Date`, `Dataset`, `Source Column`, `Security`.

## Current Implementation Notes

- `ppar/performance_comparison/report.py` still builds the report tables and
  workbook sheet DataFrames.
- `ppar/performance_comparison/workbook.py` owns XLSX presentation mechanics:
  sheet metadata, required workbook headers, workbook writing/styling,
  numeric/date formatting, and workbook artifact validation.
- Generated bundle `README.md` files now start with `Recommended Review Order`
  and then list `Audit/Export Files`. The review order calls out transaction
  and external-flow diagnostic CSVs as supplementary transaction and
  external-flow diagnostics, with transaction-matching diagnostics positioned
  as audit support for row-identity evidence.
- `manifest.json` and `review_summary.json` preserve native observed
  transaction-code strings for reviewer handoff. YAML-rule coverage still uses
  normalized transaction-code keys internally.
- The visible workbook dataset label is `Source Dataset`; prose uses the
  standardized `source-data` term, and JSON/API identifiers keep `source_data`.
- Security identifiers are treated as exact comparison keys. Regression coverage
  pins `AAPL` and `aapl` as separate securities rather than a case-insensitive
  match.
- `ppar.performance_comparison.cli.report_bundle` prints the workbook path
  before the HTML path when `--include-workbook` is used.
