# Operational Demo Data Roadmap

This roadmap covers the planned Axys and performance-comparison demo data that
will be derived from the packaged Mega-Cap Alpha Portfolio.

## Objective

Create small, believable operational demo files that share the same source
universe as the analytics demo, while staying compact enough for workbook and
Axys-demo review.

The operational demos should eventually include:

- a handful of Mega-Cap Alpha Portfolio equities;
- `CASHBAL`;
- a few T-bill and T-note style instruments with accrued interest;
- 3-6 monthly periods;
- one or two small portfolios where multi-portfolio behavior is needed;
- controlled restatements for performance-comparison examples.

## Phase 1: Prototype Generated Source Data

Status: complete.

The first prototype is generated by:

```bash
./.venv/bin/python scripts/operational_demo_data/derive_operational_demo_data.py
```

It writes only under:

```text
_demo_output/operational_demo_data_generation/
```

The generator currently:

- reads `ppar/demos/data/performance/Mega-Cap Alpha Portfolio.csv`;
- keeps a small set of high-weight equities over recent monthly periods;
- splits the original `CASHBAL` sleeve into `CASHBAL`, `TBILL13W`, `TNOTE2Y`,
  and `TNOTE5Y`;
- creates Axys-style `portperf`, `secperf`, `sec_ref`, positions, prices, cash,
  and transactions CSVs;
- writes `summary.json` for quick inspection.

The fixed-income rows are intentionally synthetic. They are designed to produce
clear accrued-interest, price, market-value, and cash examples rather than to
model CUSIP-level Treasury pricing.

## Phase 2: Manual Review

Review the generated files for:

- understandable security list;
- realistic enough cash/fixed-income sleeve;
- period count and date range;
- weights summing to 1.0;
- useful accrual and transaction examples;
- whether the file shapes look compatible with current Axys imports.

## Phase 3: Axys Analytics Demo Replacement

Status: complete.

The Axys analytics fixture is generated by:

```bash
./.venv/bin/python scripts/operational_demo_data/derive_axys_analytics_demo_data.py
```

It writes:

```text
ppar/demos/data/axys/axys_analytics/portperf.csv
ppar/demos/data/axys/axys_analytics/secperf.csv
ppar/demos/data/axys/axys_analytics/sec_ref.csv
```

The configuration file is:

```text
ppar/demos/data/axys/axys_analytics.yaml
```

The goal is for the Axys analytics demo to tell the same broad story as the
core Mega-Cap analytics demo, while still looking like an Axys-style export.
The test suite verifies that the Axys-shaped security performance is a lossless
wrapper around the canonical Mega-Cap portfolio and benchmark CSV files.

## Phase 4: Performance Comparison Snapshots

Status: generated prototype in progress.

Create snapshot A and snapshot B directories from the generated operational
data. Snapshot B should introduce small, controlled changes such as:

- one equity price change;
- one Treasury accrued-interest change;
- one cash balance change;
- one transaction amount or commission change;
- one position quantity or market-value change.

The current generator writes:

- `axys_a/`: baseline operational Axys-style snapshot;
- `axys_b/`: restated snapshot with controlled changes;
- `ppar_performance_comparison_portfolio.yaml`;
- `ppar_performance_comparison_security.yaml`.

The generated YAML files validate and run through `compare_snapshots` in strict
causal-attribution mode. They also build portfolio and security report bundles
under `_demo_output/operational_demo_data_generation/` for manual review.

The workbook should answer:

```text
This performance difference happened, and these underlying source-data
differences explain it.
```

## Phase 5: Package And Test

Once accepted:

- move selected generated files into `ppar/demos/data/axys/`;
- update demo YAML files;
- update README/demo docs;
- add contract tests for the generated operational data;
- validate the Axys analytics demo and both performance-comparison demos.
